# 验收操作清单

本清单覆盖三类尚未完成、且无法只靠自动化替代的验收：

1. 真实模型小规模评测；
2. 物理预览正式启用前的验收；
3. 读屏与移动端人工验收。

自动化测试只能证明流程、结构和构建，不能证明真实模型的题意识别、图形可读性、讲解正确性或无障碍体验。每类验收结束后分别记录结果，不要用少量样例宣称某个正确率。

---

## 0. 共同准备

- 使用独立浏览器配置，或在验收前清除模型 key；不要把 key 截图、粘贴到记录或提交到 Git。
- 固定模型、模型版本、学段、输入文本和图片；同一题重复测试时不要更换设置。
- 准备记录表（见各节），记录日期、模型、版本、学段、输入方式、耗时、结果和人工观察。
- 先在厂商后台设置消费限额/余额告警；真实模型评测会产生费用。
- 图片题使用自己拍摄或获得许可的图片，避免包含学生姓名、学校、住址等个人信息。
- 结果分为：正常完成、需要补充条件、超范围/不支持、调用失败、运行失败。不要把这些混为一类。

## 1. 真实模型小规模评测

### 1.1 准备案例

准备 20–30 道**未参与调试**的独立题目，尽量覆盖：

| 类别 | 示例 | 重点 |
|---|---|---|
| 小学普通知识 | 为什么植物需要阳光？ | 口语、学段、图文一致 |
| 小学数学/图形 | 1/2 和 1/4 哪个大？ | 图与结论一致，不超纲 |
| 初中数学 | 二次函数图像的开口和顶点 | 方法不超纲 |
| 初中科学 | 水循环/电路 | 条件与图一致 |
| 高中理科 | 函数平均变化率/能量转化 | 推理链、条件 |
| 人文学科 | 记叙文时间顺序/历史时间轴 | 图形式是否适合学科 |
| 英语/语言 | 句子结构或修改前后对照 | 不强行套数学图 |
| 图片题 | 清晰题目照片；模糊/缺条件照片 | 识别关键条件，缺条件不猜 |
| 条件不足 | “一个图形的面积是多少？”无图无数 | 应要求补充，不编造 |
| 超范围物理 | 热传导、复杂多物体 | 应说明超出工具范围或走文字退路 |

同时准备每题的独立参考答案或判断依据；物理题按 `N=mg cosθ`、`a=g sinθ`、`T=mg` 等独立计算。可直接使用 `docs/real-model-eval-cases.md` 的 14 个独立用例；它只是小规模冒烟，不是正确率认证。2026-11-13 的实际记录见 `docs/real-model-eval-results-2026-11-13.md`。

### 1.2 配置模型

1. 打开线上站点，进入系统设置。
2. 测试代理，确认 ✅。
3. 填入模型 key，测试厂商，获取模型列表，只启用 1 个模型并设为默认。
4. 记录厂商、模型名、版本（如有）、学段和日期。
5. 若要比较两个模型，分两轮进行，不要在同一轮中途切换模型。

### 1.3 逐题执行

1. 新建学习，选择对应学段和「看图讲解」。
2. 输入完整题目；图片题同时上传清晰图片。
3. 等待讲解和练习生成；记录是否正常完成、耗时和请求失败。
4. 检查讲解页：
   - 是否面向第一次接触该主题的人；
   - 图与正文、条件是否一致；
   - 是否有遮挡、裁切、不可读文字；
   - 是否超纲或把结论建立在未说明的假设上。
5. 展开每道练习的答案：
   - 题面是否自包含，是否出现“如图/原题中”等依赖讲解页的说法；
   - 答案和解析是否成立；
   - 难度标签是否与实际难度大致相符。
6. 每题至少重复 2 次（条件允许 3 次），记录稳定性；不要只记录最好的一次。
7. 条件不足题应出现“补充条件”状态，不应编造答案；图片模糊题应要求重拍或补文字。
8. 物理题使用本地预览构建（见第 2 节），不要用线上默认构建评测物理工具。

### 1.4 记录表

| 日期 | 案例 | 学段 | 模型/版本 | 图片 | 结果 | 耗时 | 讲解 | 图 | 练习 | 安全 | 备注 |
|---|---|---|---|---|---|---|---|---|---|---|---|

「结果」填正常完成/需补充/超范围/调用失败/运行失败；讲解、图、练习、安全填通过/不通过/不适用，并简述问题。

### 1.5 汇总

- 分别报告：全部题中自动完成的比例；实际展示结果中人工判定正确的比例。
- 单列失败类别：模型格式错误、网络失败、工具失败、条件不足、超范围。
- 报告题目数量、覆盖范围、模型版本和重复次数；不要用 20 题的结果宣称 90% 正确率。

### 1.6 通过标准（建议）

- 不存在把条件不足题编造成确定答案的情况；
- 超范围题有明确提示或文字退路；
- 数学/物理关键结论与独立计算一致；
- 练习没有依赖讲解页或原图的题面；
- 失败可以重试或恢复，不丢已有内容。

## 2. 物理预览正式验收

物理预览已于 2026-11-13 按用户明确授权上线（Pages `76b49aa4`），仍是有限支持范围。下面是上线前的验收流程；上线后冒烟记录见 `docs/physics-launch-checklist.md`。

### 2.1 启动预览

PowerShell：

```powershell
Set-Location -LiteralPath '.\web'
$env:VITE_ENABLE_PHYSICS = 'true'
npm run dev
```

Git Bash：

```bash
cd web
VITE_ENABLE_PHYSICS=true npm run dev
```

打开 `http://localhost:5173`，配置模型（可用真实模型；也可先用模拟服务检查流程）。

### 2.2 入口与范围

- 高中显式测试：题目前加 `【物理测试】`；支持光滑固定斜面、竖直悬挂静止、人板静力和有界电阻网络。
- 初高中纯文字题：预览分流会自动判别；小学、图片题不自动进入物理工具。
- 物理工具不支持但主题清楚：走未核验的文字退路；条件不足：进入待复核，可重试或主动改用普通讲解。
- 不带 `VITE_ENABLE_PHYSICS` 的默认构建没有物理入口或物理资源；当前生产预览构建已启用物理计算和自绘 SVG，但不含 CeTZ/字体/渲染器。

### 2.3 用例

使用 `docs/physics-development-cases.md` 的 I01–I05、H01–H03、R01–R12，并补充：

- 一个纯电阻串联/并联网络；
- 一个限定条件的人板静力题；
- 一个条件不足的物理题；
- 一个超出工具范围的物理题；
- 一个图片物理题（应不走物理工具）。

每题记录：预期（候选/复核/不支持/文字退路）、实际、模型、学段、耗时。

### 2.4 逐项检查

| 维度 | 检查内容 |
|---|---|
| 题意提取 | 质量、角度、重力加速度、拉力、表面/绳/连接条件是否与原文一致 |
| 独立数值 | 支持力/加速度/拉力/总电阻/总电流/人板接触力是否与独立计算一致 |
| 图形 | 箭头方向、漏力/多力、研究对象、标签、图例位置、遮挡、手机宽度 |
| 讲解 | 条件、假设、数值是否与图一致；是否引入新数字或新物体 |
| 练习 | 题面自包含；答案与解析使用同一组已验证结果；难度不倒退 |
| 失败恢复 | 后台线程失败、补充讲解失败、刷新恢复、跳过讲解、待复核退路 |
| 资源 | 首次加载时间、内存、压缩编译器请求、浏览器兼容性 |
| 移动端 | 390×844、360×640、平板宽度；SVG/图例/按钮是否可读可点 |

图形至少检查：研究对象、漏力/多力、箭头方向、标注和遮挡。不能因为编译成功或页面出现就判通过。

### 2.5 通过标准（建议）

- 支持范围内：独立数值检查一致，图与题目条件一致，练习自包含；
- 超范围/条件不足：不展示确定的物理结论，有明确提示或退路；
- 图形在手机和桌面无关键遮挡/裁切；
- 失败后可重试或恢复，不丢失已生成内容；
- 真实模型和真实图片的题意识别仍需人工判断，不能用格式校验代替。

### 2.6 是否上线

验收通过也不自动等于上线授权。若要启用，需要：

1. 决定正式构建是否开启 `VITE_ENABLE_PHYSICS`；
2. 单独审查压缩编译器、物理包、字体许可和部署资源；
3. 单独部署并做线上冒烟测试；
4. 明确仍属于有限支持范围，不宣称覆盖全部初高中物理。

### 2.7 验收记录（2026-11-13）

本轮在本地 `VITE_ENABLE_PHYSICS=true` 预览构建中，由使用者用已配置的真实模型逐项操作并截图确认。记录的是这些样例的实际展示结果，不是独立题库正确率，也不代表其他题型、浏览器或正式部署已经通过。

已确认：

- 光滑固定斜面：候选进入物理工具，图形、支持力/加速度结果和讲解正常。
- 竖直悬挂静止：修复后图中可见绳索，结果与 `T = mg` 一致；初中去掉 `【物理测试】` 前缀后自动分流也能进入该模型。
- 纯电阻串并联电路：进入电路适配；移动端 390 宽度下图形和文字无关键遮挡。
- 人板静力：桌面和移动端均可读；人、板、整体三幅受力图、箭头编号和图例正常，手机上滑到后两幅也没有遮挡。
- 条件不足：显式入口给出错误提示；自动分流进入待复核并可改用普通讲解。初中显式入口会提示去掉前缀后让自动分流判断。
- 超出工具范围：热传导题进入未核验的文字退路，页面保留未核验提示。
- 图片物理题：未自动进入物理工具，按普通 ELI5 图片题处理。

仍未覆盖或不能据此宣称：

- 360×640、平板、其他浏览器、深色模式下的物理固定页；
- 读屏软件对物理页面和练习卡的实际朗读；
- 未参与调试的独立题库真实模型评测；
- 图形语义的逐箭头审核、所有初高中物理题型；
- 正式站点现已启用物理预览；仍未覆盖全部题型、其他浏览器和完整手机/读屏验收。

## 3. 读屏与移动端人工验收

### 3.1 读屏工具

- Windows：NVDA（免费）或系统讲述人；
- macOS：VoiceOver（`Cmd+F5`）；
- iOS：设置 → 辅助功能 → 旁白；
- Android：设置 → 辅助功能 → TalkBack。

至少选一个桌面读屏 + 一个手机读屏；不需要每种都测。

### 3.2 读屏检查顺序

1. **首次进入**：弹窗是否被读作对话框；焦点是否在昵称输入框；必填项、错误提示是否可读；能否用 Tab 在弹窗内操作。若焦点能跑到背景页面，记录问题。
2. **顶栏**：站点名称、主题开关（读作开关并报告开/关）、昵称、设置按钮。
3. **模式切换**：两个模式是否读作标签页，并报告当前选中项。
4. **输入区**：输入框是否有可读名称；添加图片、模型选择、发送/停止按钮是否可读。
5. **看图讲解**：生成中状态是否播报；讲解 iframe 是否能进入并读正文；补充条件卡是否播报为状态；错误是否播报为警报；练习答案折叠是否能展开。
6. **苏格拉底**：新消息是否被播报；技能地图等级是否有文字说明；结束按钮和报告进度条是否可读。
7. **设置页**：昵称、学段、年级、外观、代理、厂商、模型控件是否有标签；显示/隐藏 key 按钮是否可读。
8. **深色模式**：切换后文字、按钮、错误/成功提示是否仍有足够对比度；焦点圈是否可见。

### 3.3 键盘检查

- 只用 Tab/Shift+Tab 能否到达所有交互控件，顺序是否合理；
- Enter 发送、Shift+Enter 换行是否正常；
- 弹窗打开时 Tab 是否会跑出弹窗（已知可能问题，记录即可）；
- 焦点是否始终可见；
- 打开/关闭弹窗、切换页面后焦点是否落在合理位置。

### 3.4 移动端检查

设备/视口建议：

- iPhone Safari（约 390×844）；
- Android Chrome（约 360×640 或 390×844）；
- 平板（768 宽）；
- 桌面窄窗口（≤700 宽，确认顶栏隐藏昵称后不溢出）。

逐项检查：

- 顶栏主题开关、头像、设置按钮不重叠；
- 侧栏在手机上变为横向列表，可滚动；
- 输入框、发送按钮、图片移除按钮可点；
- 讲解 iframe 高度合适，可滚动，全屏按钮行为（iOS 可能不支持）；
- 练习卡、折叠答案、报告卡不横向溢出；
- 键盘弹出时输入框不被完全遮挡；
- 横竖屏切换后布局正常；
- 深色模式下文字/图/按钮可读；
- 图片上传可从相册/相机选择，方向正确，透明图不变黑。

### 3.6 自动化语义与布局检查记录（2026-11-13）

本轮使用 ZCode 内置 Chromium 做只读语义检查和视口检查，**没有使用 NVDA/VoiceOver/TalkBack**，因此不能替代真实读屏验收。覆盖 1280×720、768×900、390×844、360×640 和深色模式。

已确认：

- 欢迎弹窗有 `role="dialog"`、`aria-modal`、由标题命名；昵称框获得初始焦点；Tab/Shift+Tab 在弹窗内循环，不会跑到背景；关闭后焦点还给原控件。
- 头像、学段、年级按钮有 `aria-pressed` 选中状态；昵称有 `required`、错误时 `aria-invalid` 和 `aria-describedby`；错误文本 `role="alert"`。
- 主题开关读作 `switch` 并暴露 `aria-checked`；学习模式读作 `tablist`/`tab`，选中项有 `aria-selected`；会话内容有 `tabpanel` 并通过 `aria-labelledby` 关联。
- 侧栏有导航地标和名称；当前会话有 `aria-current`；删除按钮的名称包含会话标题，不再是一排相同的“删除”。
- 首个 Tab 焦点是“跳到输入框”，获得焦点时可见，按 Enter 后焦点落到输入框。
- 聊天记录 `role="log"` + `aria-live="polite"`；生成中设置 `aria-busy`，流式文本对读屏隐藏，只播报“正在思考/回复”和最终消息，避免逐字重复朗读；输入框有可读名称；发送按钮禁用状态正确。
- 390 和 360 宽度没有页面横向溢出；顶栏主题开关/头像/设置不重叠；输入框、模型选择和发送按钮在视口内；768 宽度顶栏显示昵称也不溢出。
- 深色模式下正文、会话标题/日期、标签页、输入框和发送按钮的采样对比度约为 5.8:1–16:1；新增跳转链接为 16:1。没有发现关键文字不可读。

本轮修复：删除按钮缺少会话级名称、缺少跳转链接、弹窗没有焦点循环、选择按钮不暴露选中状态、标签页与内容面板未关联。

仍未覆盖：

- 真实读屏软件的朗读顺序、重复播报和 iframe 内讲解正文；模型生成图片的 `alt` 文本；
- 苏格拉底报告进度条、结束确认、打印页的实际朗读；
- iOS/Android 键盘弹出、横竖屏切换、触摸目标尺寸和真实指针点击；
- 200% 缩放、强制颜色模式、减少动态效果偏好。

自动化工具本身在部分固定/滚动容器上的指针点击会出现超时，文档焦点丢失时也会影响 `:focus-visible` 判断；本轮用键盘和坐标点击完成了检查，不把工具超时直接判为页面缺陷，真实浏览器仍需人工复核。

### 3.7 axe-core 自动审计记录（2026-11-13）
