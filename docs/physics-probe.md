# 物理编译验证记录

2026-11-12：本地 Node.js 和桌面 Chrome 浏览器验证，使用 typst.ts 0.7.0、typed-physics 0.3.0、CeTZ 0.5.2、oxifmt 1.0.0。Typst 的归档由 `dev/fetch_typst_packages.py` 从官方包站下载；项目本地保存固定版本及哈希。npm 包版本已写入依赖及锁文件。

执行 `cd web` 后运行 `npm run test:typst-probe`。Node 测试暂时使用 Windows 的 Arial 和 Cambria 字体，仅用于本机验证，不随网站发布。浏览器原型使用本地 New Computer Modern 字体，随附来源和许可证；测试还依赖本机 Typst 归档及三项 npm 包。

已验证：

- 固定物理描述经 Typst 编译，输出场景与受力图的 SVG。
- 编译后通过 metadata 获取同一场景的 `status`、`model`、支持力和加速度。4 kg、30°、重力加速度 9.81 m/s² 的光滑斜面样例，与 `mg cos θ`、`g sin θ` 的独立计算一致。
- 一个双物体接触案例的 `model-of` 返回 `none`。
- Chrome 本机测试可以输出 SVG 和结果；此样例的重力箭头向下，支持力箭头垂直斜面向外。开发服务器会对 `.tar.gz` 返回 gzip 传输编码，浏览器自动解压后会使二次解包失败；测试静态资源改用 `.bin` 文件名，并检查 gzip 文件头。
- 浏览器已运行光滑斜面和竖直悬挂静止两个模拟模型的端到端样例：提取题面依据、生成图文、计算核对、拦截条件不足。极小角度例子中物理库将加速度取成零，独立数值校验会拒绝该结果。
- 漂浮/悬挂场景现在显式绘制绳索：typed-physics 的 `hanging:` 只负责放置物体和提供支持力语义，不会自动画出绳子；如果没有显式 `rope(...)`，图中只有天花板和物块。
- 物理包的受力枚举会输出力的种类和方向，程序将它们与独立规则比较。此检查不代替对最终 SVG 箭头几何和画面布局的验收。
- 编译器原始 WASM 大于 Cloudflare Pages 的 25 MiB 单文件限制。独立构建在输出前压缩为约 10.84 MB 的 `.bin` 资源，运行时在后台线程解压并校验原始文件 SHA-256。Node 测试使用真实解压数据完成两类求解；受控 Chrome 浏览器也成功请求压缩资源，并完成解压、校验及两个模拟模型样例。在 390 × 844 的模拟视口下，两个样例和取消任务检查同样通过；这不是手机实机测试。浏览器不支持 `DecompressionStream` 时明确报错。
- `cc.query()` 在当前版本会因世界未编译失败；应在同一个 `runWithWorld` 内先编译再查询。SVG 和查询目前分别编译同一份源，正式接入时仍应评估共享编译及状态同步。

**尚未验证：** 更多浏览器、手机内存与加载时间、可分发中文和数学字体、其他题型的图内遮挡与箭头视觉审核、题目解析和练习。数值一致不能证明题目识别正确或其他图形正确。本机测试未接入学生页面，不构成产品能力或 90% 正确率结论。原「人和板」题仍超出当前已验证范围。

当前已有显式测试入口：高中学段的看图讲解中，题目前加 `【物理测试】`。原有单物体原型处理已明示质量、角度、固定光滑斜面和「只受重力和支持力」的题目，或已明示质量、静止、固定竖直绷紧的绳和「只受重力与绳拉力」的悬挂题；不支持图片。它会标注待审核，不能作为正式教学内容。原文包含某个片段并不能证明模型理解了其语义；自动计算通过也不等于题面识别正确。该入口在 Vite 开发模式或显式开启预览构建时可用，默认构建不会开放。

另新增一种人板静力开发原型：人站在水平板上，板由地面支持，固定绳竖直绷紧且向上拉人，人和板均静止；题面须明确质量、绳对人的拉力和无额外外力。以人、板、人板整体分别绘制受力方向图，图下列出对应力及数值；箭头长度不代表力的大小。它使用独立静力计算，不是 typed-physics 求解；绳拉板、未知拉力、水平拉力、摩擦、运动、转动、接触消失或其他连接方式仍需复核。题目提取及图文仍需人工审核。

开发入口现在分两步：先由现有物理流程生成图、计算结果和练习，再将题目、结构化结果和图外文字说明交给遵循 ELI5 原则的模型生成补充讲解。程序保留原始物理图和结果，不让模型改写 SVG；讲解文本作为纯文本转义后插入页面，格式不合要求时最多重试一次。模型生成的讲解、题目理解与最终图文关系并未被自动证明正确，仍须审核。若讲解生成失败，页面保留候选物理图和结果并显示错误，不显示生成成功的练习；用户可单独重试讲解，不必重新计算和绘图，也可以选择保留物理图和固定练习、跳过补充讲解。跳过不会补写未经核验的文字，物理预览标记仍然保留。

已核对随固定版本归档附带的 README：typed-physics 自身还提供其他力学图与有限范围的求解模型，以及直流串并联电路的声明、绘图和计算。网站现增加有界电阻网络适配；其余能力仍未接入。后续应按库的结构化声明能力扩展，而不是逐题硬编码，也不能让模型直接生成任意 Typst 源码执行。库能绘制某个场景不代表它能对该场景求解；其他领域的可用范围也需分别核查。

`npm run test:physics-eli5` 检查提示词、事实传递、图与结果保留、格式错误、取消和文本转义。`npm run test:typst-probe` 还使用真实 typed-physics 编译图和结果，再用模拟模型生成讲解检查组合；这不是对真实语言模型讲解质量的评测。默认构建不启用物理入口，也不包含压缩编译器。

显式设置 `VITE_ENABLE_PHYSICS=true` 的预览构建会为初高中纯文字题先调用模型判断：候选题经过模型与计算检查后生成图文；明确非物理的题目进入普通 ELI5；题目主题清楚但工具不支持时进入仅文字的 ELI5，并标明未经过物理工具核验；条件不足或分类不明确时提示复核。初中可尝试悬挂静力模型和下述纯电阻网络，其余已识别候选转文字讲解，以免固定模板超出年级。图片题与小学题仍走普通 ELI5，并提示没有经过物理工具核验；原有 `【物理测试】` 入口仍可用。

纯电阻电路适配采用有界树结构表示串联与并联，支持明确写出的理想直流电源、正电压、欧姆阻值和完整连接关系，计算总电阻及电源总电流。最多支持八个电阻、四层嵌套；零电压、开关、电表、电容、电感、内阻及其他待求量暂不支持，其中零电压是当前物理库的输入限制。程序检查数值、原文片段和部分明确的超范围条件，用独立串并联化简核对库返回的总电阻和电流，再把库的电路图、结果和固定练习交给 ELI5 补充讲解。原文片段包含元件与“串联”“并联”并不能证明模型识别了正确拓扑，预览结果必须复核，不能声称支持所有电路题。

当前电阻名称要求使用题面中的短英文字母与数字（如 `R1`）；电压和阻值分别只接受伏特与欧姆的直接数值，可使用科学计数法，暂不进行千欧等单位换算，也不直接解析算式或带分隔符的数值。题面需要明确“理想直流电源”和“纯电阻”等条件，以及要求总电阻或总电流；图片电路尚不能进入此适配。

其他已支持模型对标记为题面给定的质量、角度、重力加速度与拉力，也要求原文证据同时包含数值和对应单位；支持科学计数法，但不换算单位或求值表达式。条件类证据还必须正面包含条件词：光滑斜面同时出现“光滑”和“固定”，静止出现“静止/不动”，绳出现“竖直”且有绷紧/悬挂等表述，无额外外力出现“只受/仅受/没有其他外力”等排除语；只有片段出现在原文中不再通过。数值不完整、单位无法核对或条件词缺失时转入待复核；未给出重力加速度时的默认值仍须作为假设展示。原文匹配并不能证明模型把数值绑定到了正确的物体或理解了整个题意。

`npm run test:circuit-model` 检查有界结构、原文证据、错误数值和代码注入；`npm run test:circuit-probe` 使用真实 typed-physics 编译图与结果，再连接模拟 ELI5 讲解。本地独立浏览器使用真实后台线程和模拟接口完成了一次电路融合流程；这不是对真实模型题意识别、图形可读性或讲解质量的评测。

开发服务器中的 `physics-failure-probe.html` 使用模拟提取结果并故意使后台线程启动失败，检查页面将其标记为物理工具错误并保留重新生成入口；随后恢复线程、模拟 ELI5 讲解失败，再重试讲解，确认复用已有物理结果且不重复启动线程。探针还检查损坏的已保存结果会被拦截，旧图不再展示。探针不使用真实密钥或请求外部模型。

恢复已保存的候选结果时，程序重新验证结构、数值和页面文字模板，并从核对后的数据重新生成练习；不一致时丢弃该候选并提供重新生成入口。这不能证明 SVG 的每个几何元素与题意一致，也不代替视觉审核。

此分流使用额外的一次模型调用，模型可能误判学科、条件或是否支持，格式校验不能证明判断正确。not_applicable/unsupported 输出可以附带简短的 reason 等说明；如果同时给出 model 字段，视为与状态矛盾并转入复核。文字退路由程序将模型输出转为纯文字并用固定页面展示；练习和重新生成的练习也会拒绝图片及外链。但文字和练习仍未经物理工具核对，不能据此声称正确。预览构建用于开发，不能仅凭打开开关就发布。

预览分流遇到 `needs_review` 时会保留「重新生成讲解」入口，并提供「改用普通讲解（不做物理核验）」的主动退路：只生成纯文字讲解和文字练习，不展示物理图，页面持续标注未核验。该退路必须由使用者点击，不会自动绕过物理检查；文字内容仍未经物理工具核对。`npm run test:eli5`、`npm run test:eli5-view` 与 `npm run test:fusion-routing` 覆盖对应状态、视图和请求顺序。

预览模式会先加载分流代码；只有出现可处理的候选题时，才加载物理后台线程客户端和物理补充讲解模块。本地浏览器用模拟接口检查了普通数学主题不加载这两个模块，而电路候选会按需加载。这减少了无关资源加载，但不消除分流模型的额外调用和误判风险。

本地受控浏览器配合模拟厂商检查了三种请求路线：非物理题依次请求分类、普通讲解和练习；支持的斜面题在后台物理计算后请求 ELI5 讲解；模拟的超范围物理主题请求文字讲解和练习。浏览器观察工具在沙箱 iframe 处中断，以上是请求记录及后台流程的证据，不是最终页面视觉验收，也不是对真实模型分类或讲解质量的评测。

后续在独立浏览器中重新运行了受支持题目的融合流程：浏览器使用真实 typed-physics 后台线程，模拟接口记录了物理提取和 ELI5 讲解两次请求，页面 DOM 包含讲解框及补充讲解。另一个超出工具范围的模拟主题依次进入分类、文字讲解和练习，页面包含未核验提示；非物理主题也已验证能进入普通图文讲解与练习。讲解 iframe 的资源策略也在独立本地对照测试中阻止了外部图片请求。这验证了本机场景的流程与资源隔离，不构成最终图形视觉验收或真实模型质量评测。

`npm run test:fusion-routing` 使用本地模拟接口检查上述分流及请求顺序，也包含数学、生物和语文主题，无需真实 API 密钥。模拟回答是固定内容，只检查流程，不评估各学科答案。该检查使用模拟渲染器；真实物理库的编译和结果检查由 `npm run test:typst-probe` 与 `npm run test:circuit-probe` 单独完成。

`npm run test:physics-preview-build` 在临时目录分别构建默认版和显式预览版，检查前者不含预览运行代码及编译器，后者包含所需资源且压缩编译器小于 25 MiB，并使用该构建产物实际编译样例。样例检查现在读取项目内的字体和物理包，不依赖 Windows 系统字体或临时下载缓存。该检查不发布网站，不代替部署环境和真实模型的验证。

可在开发服务器打开 `person-board-probe.html`，此页使用模拟提取结果和真实浏览器后台线程，不调用真实模型。`npm run test:person-board` 检查人、板及整体的力平衡、作用与反作用、缺失或矛盾条件和篡改结果。当前资料未保存原始人板题的完整题面，不能确认此原型与原题场景相同，也不能宣称已解决原题。

人板原型的进阶练习会改变人的质量与绳拉力，并对新条件重新建模计算；若新条件不符合模型范围则回退为原条件。原文依据检查要求给出人、板、地面和绳的明确连接条件以及排除额外外力的语句；这只能过滤部分不完整的提取，不能证明模型理解了题意。

正式接入前仍须完成压缩资源在更多浏览器及部署环境的验证、依赖及字体许可审查、资源加载与隔离策略、图形和文字的一致性检查、超范围处理及独立题库评测。默认构建不启用物理入口，也不输出压缩编译器；不能只打开预览构建开关就发布。不要将任意模型输出直接作为 Typst 源码执行。
